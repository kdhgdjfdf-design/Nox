# المدرّب الذكي — إعداد الخادم الوسيط (Cloudflare Worker)

هذا الخادم يستقبل السؤال من المدرّب، ويستخدم OpenAI Responses API وأداة البحث على الويب عند الحاجة، ثم يعيد الإجابة وروابط المصادر المستخرجة من الاستشهادات الفعلية. أُضيفت تعليمات لتحليل صياغة السؤال والأسئلة المركّبة، وتفضيل المصادر الرسمية للملاكمة والصحة. مفتاح OpenAI يبقى داخل Cloudflare ولا يصل إلى المتصفح أبدًا.

**مهم:** وجود الخادم لا يعني أن واجهة GitHub Pages متصلة به تلقائيًا. يجب ضبط `COACH_API_URL` في `coach-preview.html` على عنوان Worker المنشور الصحيح. ما دام العنوان فارغًا، فالواجهة تستخدم إجابات محلية محدودة ولا تجلب معلومات حيّة.

## الملفات
- `worker.js`: منطق الخادم (التحقق من الطلب، والاتصال بالنموذج، واستخراج الإجابة والمصادر).
- `wrangler.toml`: إعدادات النشر والمتغيرات غير السرية.

## الأسرار والمتغيرات
| الاسم | النوع | الوصف |
|---|---|---|
| `OPENAI_API_KEY` | سر (Secret) | مفتاح OpenAI. يُضاف بالأمر ولا يُكتب في أي ملف. |
| `OPENAI_MODEL` | متغير | النموذج المستخدم. القيمة الافتراضية `gpt-5.5` (تحقق أنه متاح لحسابك). |
| `ALLOWED_ORIGINS` | متغير | عنوان موقعك المنشور، مثل `https://kdhgdjfdf-design.github.io`. افصل بينها بفاصلة. |
| `MAX_QUESTION_CHARS` | متغير | أقصى طول للسؤال (500). |
| `RATE_LIMIT_PER_MIN` | متغير | أقصى عدد طلبات في الدقيقة لكل عنوان IP (10). |

## خطوات النشر
1. ثبّت Node.js، ثم افتح جذر المستودع الذي يحتوي `worker.js` و`wrangler.toml` في الطرفية.
2. سجّل الدخول إلى Cloudflare:
   ```
   npx wrangler login
   ```
3. أضف مفتاح OpenAI كسر. سيطلب منك الأمر إدخال المفتاح، والصقه هناك:
   ```
   npx wrangler secret put OPENAI_API_KEY
   ```
4. افتح `wrangler.toml` وعدّل `ALLOWED_ORIGINS` إلى عنوان موقعك الحقيقي. العنوان يكون النطاق فقط (بدون `/shadowbox`). إن كنت تستخدم معاينة محلية أضف عنوانها أيضًا.
5. انشر الخادم:
   ```
   npx wrangler deploy
   ```
   سيعطيك رابطًا مثل `https://shadowbox-nox-coach.<name>.workers.dev`.
6. في ملف `coach-preview.html`، ابحث عن السطر:
   ```js
   const COACH_API_URL = "";
   ```
   واكتب بين علامتي التنصيص الرابط مع المسار:
   ```js
   const COACH_API_URL = "https://shadowbox-nox-coach.<name>.workers.dev/api/chat";
   ```
7. احفظ `coach-preview.html` وادفع التغيير إلى `main`. سيجري نشر صفحة GitHub Pages وفق إعدادات المستودع.

## اختبار سريع
1. افتح التطبيق، ثم المدرّب الذكي، واكتب: "ما تاريخ الملاكمة؟"
2. يجب أن تظهر إجابة، وتحتها روابط مصادر حقيقية قابلة للنقر.
3. إذا ظهرت رسالة "غير متصلة بعد": `COACH_API_URL` فارغ أو غير صحيح.
4. إذا ظهرت رسالة عن المفتاح أو الاستخدام: راجع `OPENAI_API_KEY` ورصيد الحساب.
5. لاختبار الخادم مباشرة من الطرفية (بعد النشر):
   ```
   curl -X POST https://<your-worker>/api/chat -H "Content-Type: application/json" -H "Origin: https://kdhgdjfdf-design.github.io" -d "{\"question\":\"ما تاريخ الملاكمة؟\"}"
   ```

## التكلفة والحدود
- OpenAI تحاسب على استهلاك النموذج، وأداة البحث على الويب لها تكلفة إضافية لكل عملية بحث. ضع **حد إنفاق شهريًا** من لوحة OpenAI قبل النشر.
- حد الطلبات داخل الخادم تقريبي (لكل نسخة من الخادم)، وللحماية الكاملة أضف قاعدة **Rate Limiting** من لوحة Cloudflare على المسار `/api/chat`.
- الخادم لا يخزن المحادثات ولا بيانات المستخدم.

## ملاحظات مهمة
- يُطلب من النموذج البحث عند الأسئلة الواقعية التي تحتاج تحققًا، مع تفضيل الجهات الرسمية مثل World Boxing وOlympics وUSA Boxing وEngland Boxing، ومصادر الصحة العامة مثل NHS وCDC. يظل اختيار البحث من النموذج نفسه؛ لا يمكن ضمان البحث في كل سؤال.
- لا تعرض الواجهة مصادر حيّة ما لم يكن `COACH_API_URL` مضبوطًا على Worker صالح؛ رابط Worker يجب نسخه من ناتج نشر Cloudflare ولا ينبغي تخمينه.
- المصادر تُستخرج من بيانات الاستشهاد التي يعيدها الـ API، ولا تُستخرج من نص الإجابة.
- إن لم يُضبط `OPENAI_API_KEY` يعيد الخادم رسالة واضحة بأن الخدمة غير متصلة.
